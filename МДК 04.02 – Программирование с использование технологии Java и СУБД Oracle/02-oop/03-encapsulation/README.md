# Инкапсуляция

## Цель занятия
Научиться защищать состояние объекта и менять его только через контролируемые методы.

## Что сегодня изучаем?
- Модификаторы `private` и `public`.
- Методы доступа и изменения.
- Проверка допустимости состояния.

## Основная терминология
| Термин | Определение |
| ------ | ----------- |
| Инкапсуляция | Сокрытие деталей и контролируемый доступ к состоянию |
| `private` | Доступ только внутри класса |
| `public` | Доступ из других классов |
| Валидация | Проверка корректности значения |

## Теория
Если сделать поля доступными всем, любой код сможет записать в баланс отрицательное значение или установить цену ниже нуля. Инкапсуляция закрывает поля модификатором `private` и предоставляет методы, которые поддерживают правила объекта.

Геттер возвращает значение, сеттер или предметный метод меняет его после проверки. Не каждому полю обязательно нужны оба метода: API класса должен разрешать только осмысленные действия.

## Базовый синтаксис
```java
class BankAccount {
    private int balance;
    public int getBalance() { return balance; }
    public boolean deposit(int amount) {
        if (amount <= 0) return false;
        balance += amount;
        return true;
    }
}
```
Поле закрыто; пополнение возможно только положительной суммой.

## Практические примеры
### Пример 1. Цена товара
Поле `price` закрыто; метод изменения принимает только цену больше нуля.
### Пример 2. Банковский счёт
Методы пополнения и снятия проверяют сумму и доступный баланс.

## Разбор примера
В демо баланс нельзя присвоить напрямую. Метод `withdraw` сначала проверяет сумму и остаток, а при ошибке оставляет состояние без изменений.

## Итоги занятия
- Состояние обычно скрывают в `private` полях.
- Публичные методы формируют контролируемый интерфейс класса.
- Проверка выполняется до изменения состояния.
