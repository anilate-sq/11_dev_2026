# Интерфейсы

## Цель занятия
Научиться описывать общий контракт интерфейсом и реализовывать его разными классами.

## Что сегодня изучаем?
- Объявление интерфейса.
- Реализация через `implements`.
- Полиморфная работа с интерфейсным типом.

## Основная терминология
| Термин | Определение |
| ------ | ----------- |
| Интерфейс | Контракт операций, доступных реализующим классам |
| Реализация | Класс, предоставляющий тела методов интерфейса |
| `implements` | Объявление реализации интерфейса классом |
| Контракт | Набор обещанных операций и их смысла |

## Теория
Интерфейс описывает, что объект умеет делать, не привязывая вызывающий код к конкретной реализации. Например, `Payable` может иметь метод `pay`, а банковская карта и электронный кошелёк реализуют его по-разному.

Класс использует `implements` и должен реализовать абстрактные методы интерфейса. Переменная интерфейсного типа может ссылаться на любой объект, реализующий этот интерфейс; это форма полиморфизма.

## Базовый синтаксис
```java
interface Payable {
    void pay(double amount);
}
class Card implements Payable {
    public void pay(double amount) {
        System.out.println("Оплата картой: " + amount);
    }
}
```
Реализация метода должна быть `public`, поскольку метод интерфейса публичен.

## Практические примеры
### Пример 1. Печать документов
Классы `Invoice` и `Label` реализуют контракт `Printable`.
### Пример 2. Уведомления
Email- и SMS-отправители реализуют `Notifier` и обрабатываются одним методом.

## Разбор примера
В демо список получателей хранится как `Payable[]`; каждый объект выполняет оплату своим способом, а вызывающий код зависит только от контракта.

## Итоги занятия
- Интерфейс объявляет общий контракт поведения.
- Класс реализует его через `implements`.
- Интерфейсный тип позволяет обрабатывать разные реализации одинаково.
