# Разбор задач у доски: закрепление ООП

**Формат:** коллективное программирование в VS Code, разбор ошибок и обсуждение решений.  
**Продолжительность:** 90 минут.  
**Подготовка:** пройдены классы, объекты, конструкторы, инкапсуляция, наследование, полиморфизм и интерфейсы.

## Цель занятия

Научиться самостоятельно выделять сущности, определять их состояние и поведение, применять конструкторы, защищать данные, использовать наследование и полиморфизм.

## План пары

| Этап | Время |
| --- | ---: |
| Повторение: класс, объект, `this`, `private`, `extends`, `@Override` | 10 мин |

**Принцип:** сначала студенты предлагают поля, конструкторы и методы, затем пишем код вместе. Готовые реализации в папках нужны преподавателю для проверки и демонстрации *после* обсуждения.

## Задача 1. Банковский счёт (25 минут)

**Ситуация:** банк предоставляет клиентам счета, которые можно пополнять и с которых можно снимать деньги.

Нужно разработать класс `BankAccount`:
1. Поля `owner` и `balance` должны быть закрытыми.
2. Конструктор задаёт владельца и начальный баланс.
3. Метод `deposit(double amount)` пополняет счёт.
4. Метод `withdraw(double amount)` снимает деньги.
5. Сумма операции должна быть строго больше нуля; нельзя снять больше доступного остатка.
6. Метод `showInfo()` показывает владельца и остаток.
7. В `main` создать два счёта и показать успешные и ошибочные операции.

**Вопросы для обсуждения:** зачем `private`? Почему изменение баланса лучше разрешать только через методы? Как проверить параметры конструктора? Почему при неуспешной операции баланс не должен измениться?

**Разбор:** [01-bank-account/Main.java](01-bank-account/Main.java).  
**Что показать:** пополнение, снятие, недостаток средств и отрицательную сумму.

## Задача 2. RPG-персонажи (35 минут)

**Ситуация:** персонажи участвуют в пошаговом сражении.

Создайте базовый класс `GameCharacter` с полями `name`, `health`, `attackPower`, конструктором и методами:
- `attack(GameCharacter target)` — атаковать указанного персонажа;
- `takeDamage(int damage)` — получить урон, не опуская здоровье ниже 0;
- `isAlive()` — проверить, жив ли персонаж;
- `showStatus()` — вывести состояние.

Далее:
1. Создайте `Warrior extends GameCharacter` с увеличенным стартовым здоровьем.
2. Создайте `Mage extends GameCharacter`, переопределяющий `attack()` (усиленный урон).
3. Проведите обмен атаками.
4. Создайте массив `GameCharacter[]` из разных персонажей и вызовите их общий метод `showStatus()`.

**Вопросы:** что вынести в базовый класс? Что наследуют потомки? Зачем `super(...)`? Почему у разных персонажей вызываются разные реализации `attack()`? Как работает полиморфизм?

**Разбор:** [02-rpg/Main.java](02-rpg/Main.java).  
**Усложнение по желанию:** запретить атаку мёртвым персонажем и по мёртвой цели (в готовом примере это уже предусмотрено).

## Задача 3. Найдите ошибку (15 минут, резерв)

Покажите конструктор класса `Student`:

```java
public Student(String name, int age) {
    name = name;
    age = age;
}
```

**Предскажите результат:** почему после создания `new Student("Alex", 18)` выводится `null, 0`? Найдите причину и исправьте код, используя `this`.

**Разбор с намеренно сохранённой ошибкой:** [03-debug-student/Main.java](03-debug-student/Main.java).

## Как запускать

Откройте любую папку задачи в VS Code и запустите `Main.java` через Java Extension Pack либо в терминале из папки соответствующей задачи:

```bash
javac Main.java
java Main
```

Каждая папка — отдельный независимый пример: одинаковые имена `Main` не конфликтуют при запуске из своей директории.

## Итоги занятия

- Поля и методы описывают состояние и поведение объекта.
- Конструктор помогает создать объект с корректным начальным состоянием.
- Инкапсуляция защищает данные от некорректного изменения.
- Наследование позволяет переиспользовать общее поведение.
- Полиморфизм позволяет вызывать разные реализации через общий тип.
